# King Health website: handoff guide for an AI assistant

Paste this whole file into a new conversation with any AI assistant before asking it to change the King Health website. It explains what the site is, how it is built, where every piece of content lives, how to rebuild and publish it, and the rules the site must keep. It does not assume the assistant has any special tools or skills.

## 1. What this project is

- The marketing website for **King Health LLC**, an independent insurance advisory owned by **Javon King** in Newark, New Jersey.
- It describes four coverage categories (Senior Benefits, Individual Benefits, Group Benefits, Retirement) and twelve products, shows Google reviews, and invites visitors to request a consultation, call, or save Javon's contact card.
- It is **plain static HTML, CSS and a small amount of JavaScript**. There is no framework (no React, no WordPress, no Node build). Pages are generated by one Python script from one JSON content file.
- Hosting today: **Cloudflare Pages**, project `king-health`, preview address `https://king-health.pages.dev`. It deploys automatically from the GitHub repository `tealapexgroupjh/king-health`, branch `main`, folder `public/`.
- A second copy runs in **Javon's own Cloudflare account** as a Direct Upload project named `kinghealth` (address `https://kinghealth.pages.dev`). It is not connected to GitHub. To update it: rebuild, then in Cloudflare open Workers and Pages, `kinghealth`, choose Create deployment (new deployment), and drag in the `public/` folder.
- The final custom domain has not been chosen yet. Until it is, links and search data point at `https://kinghealthdirect.com` (set in `seo.base_url`).

Never hand edit files inside `site/` or `public/`. They are overwritten on every build. Make every change in `_build/` and rebuild.

## 4. How a change is made

1. Edit `_build/content.json` (or `photos.json`, `reviews_google.json`, or a file in `_build/src/`).
2. Rebuild. On the Mac, double click `BUILD.terminal`, or run:
   - Review build: `python3 _build/build.py` (writes `site/`)
   - Launch build: `python3 _build/build.py --release` (writes `site/` too, so the BUILD button runs it in a temporary copy and then copies the result into `public/`)
   - The build needs Python 3 plus the `Pillow` and `segno` packages (`python3 -m pip install --user pillow segno`).
3. Run checks: `python3 _build/release_check.py` (add `--strict` to fail on remaining placeholders).
4. Publish: double click `PUSH_TO_GITHUB.terminal`. Cloudflare redeploys within a minute or two.

### Review build versus launch build

| | Review (`site/`) | Launch (`public/`) |
| --- | --- | --- |
| Search engines | Blocked (`noindex`, robots disallow) | Allowed on the real domain; the `pages.dev` address stays blocked through `public/_headers` |
| Sitemap | None | `sitemap.xml` |
| Draft blog posts and placeholders | Shown and marked | Removed |
| Auto refresh after rebuild | Yes (`assets/build-stamp.txt`) | No |

## 5. Where common things live in `content.json`

| To change | Edit |
| --- | --- |
| Phone, email, hours, address, license, social links | `site` (`phone`, `email`, `hours`, `hours_structured`, `address`, `license_number`, `licensed_in`, `social`) |
| WhatsApp link | `site.social.whatsapp` (format `https://wa.me/1XXXXXXXXXX?text=...`); currently set to the main number, which must have WhatsApp |
| Hide or show a page | `site.hidden_pages`. Keys: `reviews`, `join-the-team`, `blog`, `terms`, `carriers`, `about`. Blog and Join the Team are hidden today. A hidden page is not generated and every link to it disappears. |
| Second navigation bar | `site_nav` |
| Home hero text | `home.hero_heading`, `home.hero_lede` |
| Home slideshow photos | `home.hero_slides.items` (file name in `_build/hero_slides/`, `alt` text, `pos` focus point like `50% 30%`) and `interval_seconds` |
| Category pages | `categories.<slug>` (slugs: `senior-benefits`, `individual-benefits`, `group-benefits`, `retirement`) |
| Product pages | `products.<slug>` (`medicare`, `final-expense`, `ancillary`, `individual-health`, `whole-life`, `term-life`, `dental-vision`, `group-health`, `group-life`, `group-dental-vision`, `annuities`, `indexed-universal-life`) |
| About page | `about` |
| Contact card and QR code on the About page | `site.contact_card` (names and title; phone, email and address come from `site`) |
| Reviews page text | `reviews` |
| Terms page | `terms` (effective date and governing state are still placeholders) |
| Search titles, descriptions, domain, service areas | `seo` (`base_url`, `service_areas`, `service_areas_confirmed`, `pages.<file>.seo_title` and `seo_description`) |

Photos: `_build/photos.json` maps a slot (for example `banner_medicare`) to a file in `site/media/photos/` with a focus point. To swap a page photo, add the new file to `site/media/photos/`, point the slot at it, and rebuild.

## 6a. Lead form to GoHighLevel (live as of 2026-10-25)

The site keeps its own custom consultation form (not the generic GoHighLevel form) and posts each submission as JSON straight to a GoHighLevel inbound webhook. No server, no API key in the page.

| Piece | Value |
| --- | --- |
| Where the URL lives | `ghlWebhookUrl` in `_build/src/site.js` (empty string means demo mode) |
| Webhook URL | `https://services.leadconnectorhq.com/hooks/3EReOYEGztjvr04Cu0rd/webhook-trigger/c4e7bd00-d5a0-4e2d-99f4-ce3ba448a8e6` |
| GoHighLevel workflow | "Website Lead: King Health site form (test)", published, in the King Health sub-account |
| Fields sent | `first_name`, `last_name`, `phone`, `email`, `category`, `coverage`, `message`, `consent_contact`, `consent_sms`, `source` (`king-health-site`), `page`, `submitted_at`, `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content` |

Workflow steps, in order:
1. Inbound Webhook trigger.
2. Create contact: first name, last name, phone, email mapped from `{{inboundWebhookRequest.*}}`; contact source "Website Lead".
3. Add tag: `website lead`.
4. Create opportunity: pipeline "1.1 Medicare Marketing Leads", stage "New Lead", opportunity source "Website Lead", not assigned to anyone.
5. Internal notification email to Javon@kinghealthdirect.com with every submitted field (sent from the account's default sender).

Notes:
- The inbound webhook trigger is a premium GoHighLevel trigger and may be billed per run; check the account's workflow billing.
- If the webhook ever fails, the visitor sees an error asking them to try again or call (973) 524-7188; nothing is lost silently.
- A test lead named "Test WebsiteLead" (test.websitelead@example.com) was created on 2026-10-25 to prove the flow and can be deleted.
- To change routing (assign a user, a different stage, SMS alert), edit the workflow in GoHighLevel; the site does not need to change. To change the URL, edit `site.js`, rebuild, and publish.

## 8. Rules the site must keep

- No em dashes or en dashes anywhere in visible text, titles or descriptions. Do not use hyphens as sentence punctuation. Visible copy avoids numerals except where unavoidable (phone, license, ratings); the lint enforces this.
- No emoji in the site.
- Never invent reviews, ratings, review counts, statistics, licenses or testimonials. Ratings and reviews come only from Google.
- Only list states where Javon is licensed.
- Keep the visual format: integrate new sections with the existing classes and components instead of redesigning. Add rather than remove.
- Headings use the Manrope font and body text uses Inter. No decorative serif fonts.
- Do not imply that people in stock photos are King Health clients.
- Keep all images inside the site folder (no hotlinking to other websites), so nothing breaks.

## 9. How to verify a change

1. `python3 _build/build.py` reports 0 warnings.
2. `python3 _build/release_check.py` shows no FAIL lines.
3. Open the changed pages through a local web server (for example `cd site && python3 -m http.server 8000`, then visit `http://localhost:8000`) at desktop and phone widths, and confirm nothing scrolls sideways.
4. After pushing, refresh `https://king-health.pages.dev` and confirm the change.

## 10. Asking an AI for help

Good requests name the page and the field, for example: "In `_build/content.json`, change the Medicare page lede to say ..., then tell me the exact JSON edit." Ask the assistant to show the exact edit, keep JSON valid (matching quotes, commas, braces), and remind you to rebuild and push.
